# SAA 2025 specifications and planning-readiness review

**Verdict: not ready.** The Next.js frontend / Go API / Supabase boundary is coherent, and all eight course categories have specifications.
The remaining blockers are anonymous-sender disclosure, incomplete upload enforcement, conflicting shared contracts, and reward/concurrency behavior that the proposed algorithms do not guarantee.
No `plan.md` or `phase-*.md` exists under this initiative; this is a review of readiness to write that implementation plan, not a review of an existing plan.
Keep the approved twelve-feature release scope, but resolve the major findings below before turning the drafts into implementation tasks.

Reviewed on 2026-11-10. Scope: `docs/SCREENFLOW.md`, all three `docs/screen-specs/*.md`, the feature list, decision log, permissions, all twelve functional and technical specifications, all feature screen specifications, and the shared wave-2 context. Figma was not accessible and was not independently verified. Findings concern the proposed specifications, not demonstrated defects in application code. No implementation tests were run.

Paths beginning `spec/` or `reports/` below are relative to `plans/261109-1626-saa-2025-website/`. Paths beginning `docs/` or `node_modules/` are relative to the repository root. Line numbers refer to the reviewed files. Severity: **critical** = specified behavior directly defeats a privacy boundary; **major** = resolve before planning the affected integration; **minor** = bounded clarification or acceptance-test correction.

## Top 5 fixes before writing the implementation plan

1. **Close the complete anonymity and attachment contract.** Resolve R01–R04 before establishing the schema/API tasks. Freeze opaque object keys, internal ownership, actual-file validation, safe cleanup and current-anonymity notification reads. Review a named-to-anonymous edit and an anonymous image kudo as a third user, inspecting every returned field/URL.

2. **Publish one Go integration/bootstrap contract and retire the stale handoff.** Fix `profiles` → `users`, define the browser CORS/preflight/export behavior, verify asymmetric Supabase signing and server database access, and specify the card/profile/error DTOs and missing-profile recovery (R05, R06, R14, R15, R21, R22). Freeze schema dependency order: F002 `users/units` → F003 `events` and F005 kudos tables → F012 `campaigns` before F008's referencing `hearts`, boxes and view → F009 notifications and F011 moderation additions. The UI priority list is not a migration order.

3. **Make reward and moderation transitions testable under concurrency and retries.** Settle R09–R13: authoritative campaign lookup must not silently award weight 1; capture hero transitions; serialize icon completion; replay an opening intent safely; version moderation decisions. Write acceptance cases for simultaneous hearts on different kudos of one sender, duplicate distinct senders, two missing icons drawn concurrently, a lost open response, and stale opposing admin decisions. Preserve the approved high-water rule and best-effort notification policy.

4. **Specify the Next.js layout and two countdown modes using the installed guides.** Resolve R07/R08 and the HTTP-status expectation in R18. Keep one document root, place full/minimal/admin chrome in appropriate nested layouts, use client route-aware navigation, and separate launch redirect behavior from ceremony display behavior. Add bounded fetch/dependency timing and deterministic temporal fixtures (R16, R23).

5. **Reconcile acceptance scope and build a small end-to-end evidence path first.** Resolve desktop/mobile conflicts and the failed-read/sanitized-content definitions (R17, R19, R20), then attach a verifiable fixture and expected result to each of the eight categories above. Keep all twelve features as G05 requires. Obtain the outstanding Figma-derived artwork, award/about/community copy and final message text for visual implementation; their absence cannot be filled with invented design facts.

The highest-risk first build should prove a company Google session reaches the separate Go API, provisions one profile, reads the seeded event, and creates/reads an anonymous kudo with a validated image. Extend that path with an x2 heart, a concurrent box grant, a retried box open, and a Spam/Public decision. This resolves architectural and data-integrity risks before polishing the tall board, word cloud, animations and admin tables. F008 heart logic and F012's campaign schema must enter this path early even though the feature list places their UI at P2/P3 (`spec/feature-list.md:33`, `:48`, `:52`).

For this course scale, the chosen stdlib router, pgx/sqlc transactions, static awards, JSON dictionaries, focus/poll refresh, CSV exports and no Redis are proportionate. Avoid adding a BFF, generic workflow/event framework, full audit history, notification outbox, search engine or materialized aggregates without measured need. The targeted transition/idempotency safeguards above implement already-promised behavior; they do not require expanding the approved release scope.
